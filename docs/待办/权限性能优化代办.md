# 权限性能优化代办

> 来源：AUTH-S4-02 权限性能检查
> 创建时间：2026-07-29
> 优先级：按重要性排序

---

## 🔴 P0 — 必须优化

### 1. 部门递归 N+1 查询
- **问题：** `DepartmentMemberService.collectDeptAndChildren()` 使用 Java 递归，每层一个 SQL
- **场景：** 5 层部门树约 121 次独立查询
- **方案 A（推荐）：** 利用 V13 迁移已预留的 `dept_path` 字段，填充路径数据后用 `LIKE '/parentId/%'` 一次查出全部下级部门
- **方案 B：** 迁移至 MySQL 8+ `WITH RECURSIVE` CTE，单次 SQL 完成递归
- **涉及文件：** `DepartmentMemberService.java`
- **状态：** ⬜

### 2. 数据范围重复解析
- **问题：** 同一请求内 `resolveDeptScopeMemberIds()` 重复调用（工作台统计 6 次、待办 5 次）
- **方案：** 在 `DataScopeService` 中加请求级缓存（`ThreadLocal` 或 `Map`），首次解析后缓存部门成员 ID 集合到请求结束
- **涉及文件：** `DataScopeService.java`
- **状态：** ⬜

---

## 🟡 P1 — 建议优化

### 3. 新增工单范围查询覆盖索引
- **问题：** `mt_ticket` 分页查询按 `assignee_id` 过滤 + `created_at` 排序，无覆盖索引导致文件排序
- **方案：** 新增 `idx_mt_ticket_scope_query(assignee_id, is_deleted, created_at DESC)`
- **涉及文件：** Flyway 迁移
- **状态：** ⬜

### 4. 工单详情 N+1 查询
- **问题：** `toDetailVO()` 每次加载工单详情额外查消息 + 事件两条 SQL
- **方案：** 可优化为批量查询或延迟加载
- **涉及文件：** `TicketBizService.java`
- **状态：** ⬜

---

## 🟢 P2 — 数据量增大后再考虑

### 5. `OR assignee_id IS NULL` 索引效率
- **问题：** 大 `IN` 列表 + `OR IS NULL` 可能影响索引范围扫描
- **方案：** 拆为两个查询 UNION
- **涉及文件：** `DataScopeService.java`
- **状态：** ⬜

### 6. 用户名/邮箱逐行查询
- **问题：** `resolveUserName` / `resolveMailboxName` 逐行 `selectById`
- **方案：** 数据量增大后可改为批量 JOIN
- **涉及文件：** `TicketBizService.java`
- **状态：** ⬜
