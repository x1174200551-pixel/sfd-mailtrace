## 1. 覆盖范围

- `GET /api/v1/work-calendars`：日历列表、摘要、关键字、默认日历筛选。
- `POST /api/v1/work-calendars`：新建工作日历。
- `PUT /api/v1/work-calendars/{id}`：编辑工作日历。
- `PATCH /api/v1/work-calendars/{id}/default`：设置或取消默认工作日历。
- `DELETE /api/v1/work-calendars/{id}`：删除工作日历和保护规则。
- `GET /api/v1/holidays`：节假日列表、摘要、日历、关键字、日期范围筛选。
- `POST /api/v1/holidays`：新建节假日。
- `PUT /api/v1/holidays/{id}`：编辑节假日。
- `DELETE /api/v1/holidays/{id}`：删除节假日。

## 3. Service 层步骤对齐

本次契约未修改后端 Service，但已按现有 Service 步骤记录页面口径：

- 工作日历和节假日配置仅管理员可访问。
- 工作日历保存校验时区、工作日、工作开始时间和工作结束时间。
- 默认工作日历唯一；设为默认接口会清理其他默认工作日历。
- 默认工作日历不能删除。
- 已被 SLA 策略引用的工作日历不能删除。
- 已配置节假日的工作日历不能删除。
- 节假日保存校验工作日历存在性。
- 同一工作日历下节假日日期唯一。
- 节假日字段按当前后端 `holidayDate + holidayName`，不扩展“是否全天”。

## 4. 页面口径

- “绑定策略数”不来自 `GET /api/v1/work-calendars`；后续前端可由 SLA 策略列表按 `calendarId` 派生 `derivedPolicyCount`。
- “本月节假日数”不来自工作日历摘要；后续前端可用当前月份节假日列表统计。
- 月历预览由前端基于工作日历和节假日列表渲染。
- SLA 计算示例仅用于页面预览，实际截止时间以后端 `SlaDeadlineService` 为准。
- 空列表、加载中、接口失败、无权限作为真实页面状态实现，不展示原型说明卡。
