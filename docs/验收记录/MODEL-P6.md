## 4. 联调中发现并修复的问题

普通处理人进入工作台时，前端使用邮箱配置分页接口加载筛选项。该分页接口需要邮箱配置查看权限，导致普通用户虽然有业务数据授权，页面仍提示“部分工作台数据加载失败”。

修复后：

1. dashboard、工单、客户、收件记录、发件记录和用户授权筛选统一调用 `/api/v1/mailboxes/options`。
2. 选项接口只返回当前用户可见范围，不开放邮箱配置管理权限。
3. 前端新增 `MailboxOption` 类型，避免用完整 `Mailbox` 类型伪装精简接口响应。
4. 普通处理人复验工作台、全部工单和客户管理均正常，管理类菜单保持隐藏，浏览器控制台 0 warning/error。

## 6. 上线与回滚门禁结论

研发侧迁移、权限、构建和浏览器门禁已通过。实际测试环境或生产环境发布仍必须满足以下条件：

1. 由操作者明确指定目标数据库，确认不是当前不可变更的远端 MySQL 5.7 服务。
2. 升级前完成目标库备份，并在独立库验证恢复。
3. 发布窗口内只通过 Flyway 顺序执行 V18、V19，不手工拆改 SQL。
4. 若升级或应用验收失败，停止新版本应用、恢复升级前备份并回滚应用镜像。
5. 禁止通过手工删除 V18/V19 新表、新列模拟数据库降级。

详细操作边界见 `docs/运维/MODEL-P6-上线与回滚说明.md`。
