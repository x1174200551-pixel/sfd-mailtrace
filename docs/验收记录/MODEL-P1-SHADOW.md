## 实施范围

1. 新增管理员、企业授权、邮箱授权和空授权的统一解析结果。
2. 新增企业/邮箱访问断言与查询目标解析能力。
3. 新增旧角色范围与新授权范围的影子对比，只记录差异，不改变放行结果。
4. 覆盖授权类型与目标字段的后端校验，MySQL 5.7 不依赖 `CHECK`。

## 实施结果

1. 新增 `EnterpriseMailboxAccessService`，支持管理员、企业授权、邮箱授权、企业与邮箱并集、历史可读和业务可操作范围。
2. 管理员可读全部未删除邮箱；普通用户空授权返回空集合，禁止空集合退化为全表。
3. 停用授权被双重过滤；停用企业或停用邮箱仍可读历史数据，但不进入可操作邮箱集合。
4. 新增企业、邮箱和处理人访问断言；跨邮箱分配会被拦截。
5. 新增请求级缓存，同一请求内同一用户只解析一次角色、授权、企业和邮箱。
6. 新增邮箱列表和工单角色范围两类影子对比；只记录用户 ID 和范围数量，不记录业务内容，异常不影响原响应，可通过配置关闭。

## 验证证据

1. 定向测试 `EnterpriseMailboxAccessServiceTest`、`MailboxAccessShadowServiceTest`、`MailboxServiceTest`、`TicketBizServiceTest` 通过。
2. `cd backend && mvn -q test` 全量测试通过。
3. 当前代码在本地配置、本地数据库、Nacos 关闭、端口 `8080` 启动成功，Flyway 校验为 V18。
4. 本地管理员真实请求邮箱列表和工单列表均返回 HTTP 200；两类影子结果均为 `legacyCount=1`、`targetCount=1`、双向差异 0。
5. 本地授权抽样：管理员 0 条显式授权但可读/可操作邮箱各 1；3 个普通用户各有 1 条默认企业授权，可读/可操作邮箱各 1。
6. P1 未修改 `PermissionService`、`DataScopeService`、`RoleManagementService` 或前端页面，旧角色数据范围在整个影子阶段仍是生产查询唯一来源。
