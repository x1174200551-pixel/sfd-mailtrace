# AUTH-S3-G0-01 组织架构范围确认稿

## 建议结论

建议进入 `AUTH-S3`，但采用轻量方案：先做本系统内置部门树和主管视角，不接外部组织架构，不单独引入团队模型。

## 本期范围

1. 组织模型只做「部门」。
2. 部门支持上下级树、启停、排序、负责人。
3. 用户支持主部门；表结构预留多部门，但第一版页面只维护主部门。
4. 现有用户统一回填到「默认部门」。
5. 新增/启用 `SUPERVISOR` 主管角色，默认具备工作台、全部工单、客户只读和必要工单处理权限。
6. 数据范围新增 `DEPT` 和 `DEPT_AND_CHILDREN`。
7. `TEAM` 暂不实现，后续如确实需要团队，可由部门先承载。

## 数据范围口径

| 范围 | 含义 | 本期是否做 |
|------|------|------------|
| `ALL` | 全部数据 | 已有 |
| `SELF` | 自己负责 + 未分配池 | 已有 |
| `DEPT` | 主部门成员负责工单 + 未分配池 | 做 |
| `DEPT_AND_CHILDREN` | 主部门及下级部门成员负责工单 + 未分配池 | 做 |
| `TEAM` | 团队成员负责工单 | 暂缓 |

客户列表、客户详情、工作台统计继续沿用“当前可见工单聚合”的口径，避免客户数据范围和工单数据范围不一致。

## 页面范围

1. 系统管理新增「组织管理」。
2. 左侧部门树，右侧部门详情和成员列表。
3. 支持新建、编辑、启停部门。
4. 支持设置部门负责人。
5. 用户管理页增加主部门字段。
6. 角色管理页的数据范围可选择 `DEPT` / `DEPT_AND_CHILDREN`。

## 不做范围

1. 不接企业微信、钉钉、飞书、LDAP 等外部组织同步。
2. 不做独立团队模型。
3. 不做指定邮箱 `MAILBOX` 数据范围。
4. 不做指定客户标签 `CUSTOMER_TAG` 数据范围。
5. 不做复杂岗位、职级、矩阵汇报关系。

## 需要谭总确认

建议确认以下口径后进入 `AUTH-S3-DB-01`：

1. 本期是否按「内置部门树 + 主管视角」推进。
2. `SUPERVISOR` 是否默认使用 `DEPT_AND_CHILDREN` 数据范围。
3. 主管是否可见未分配池。建议：可见，便于调度。
4. 第一版是否只维护用户主部门。建议：是，多部门只做表结构预留。

## 当前状态

待谭总确认。确认后进入 `AUTH-S3-DB-01 组织表结构迁移`。
