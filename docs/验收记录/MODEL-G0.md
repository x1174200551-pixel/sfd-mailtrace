## 业务门禁结论

| 编号 | 最终结论 |
|------|----------|
| BIZ-01 | 菜单保留“通知模板”，页面内按模板类型区分自动回复、分配通知和 SLA 提醒 |
| BIZ-02 | 企业停用不强制修改邮箱状态，但禁止该企业继续新收信、新建工单和参与新业务配置 |
| BIZ-03 | 邮箱未绑定可用自动回复模板时不发送自动回复，并记录配置缺失事件或发送日志 |
| BIZ-04 | 邮箱未绑定 SLA 时不计算 SLA，页面展示“未配置 SLA” |
| BIZ-05 | 非管理员用户保存时至少配置一个企业授权或邮箱授权；空授权历史账号查询业务数据为空 |
| BIZ-06 | 企业授权包含该企业未来新增邮箱，并在用户授权页面明确提示 |

## 技术基线

1. 当前分支：`权限重构`。
2. 本地配置：`backend/src/main/resources/application.yml`，后端端口 `8080`，使用本地数据库。
3. 当前 Flyway 最大版本为 V17，本阶段使用 V18；执行前仍需再次读取迁移目录。
4. 迁移脚本兼容 MySQL 5.7。
5. 用户模型固定为单角色、单部门。
6. `P0-EXPAND` 期间旧角色数据范围继续生效，不修改权限查询行为。

## 验收结论

业务门禁和技术基线已关闭，允许进入 `MODEL-P0-EXPAND`。禁止提前实施 `P1-SHADOW` 或 `P2-CUTOVER`。
