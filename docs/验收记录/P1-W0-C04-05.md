## 1. 覆盖范围

- `GET /api/v1/dashboard/summary`：工作台统计摘要。
- `GET /api/v1/dashboard/my-todos`：当前用户待办列表和摘要。
- 统计卡片：工单总数、待分配、处理中、待客户回复、SLA 已超时、今日已关闭。
- 待办列表：工单号、主题、状态、优先级、客户邮箱、SLA 截止时间、是否超时、创建时间。
- 页面跳转：工单统计卡片、SLA 风险入口、处理中入口、邮箱入口、待办详情入口。
- 四态：加载中、空列表、接口失败、无权限。
- 后续扩展边界：SLA 达成率、预警类指标、关闭时间筛选、活动流、消息流暂不纳入第一版。

## 2. 字段对齐

已对齐 `DashboardController`、`DashboardService`、`DashboardSummaryVO`、`DashboardTodoListResponse` 和 `TicketSummaryVO`：

- `totalCount`：未逻辑删除工单总数。
- `pendingAssignCount`：`status=PENDING_ASSIGN`。
- `processingCount`：`status=PROCESSING`。
- `waitingCustomerCount`：`status=WAITING_CUSTOMER`。
- `slaOverdueCount`：`sla_breached=1`。
- `closedTodayCount`：今日关闭工单数。
- `activeCount`：待分配 + 处理中 + 待客户回复。
- `records[]`：当前用户待办工单列表，使用 `TicketSummaryVO`。
- `limit`：待办返回条数限制。

## 3. Service 层步骤对齐

本次契约未修改后端 Service，但已按现有 Service 步骤记录页面口径：

- 工作台统计仅允许 `ADMIN` 和 `AGENT` 访问。
- 工作台统计按状态、SLA 超时、今日关闭分别计算核心指标。
- `activeCount` 由待分配、处理中、待客户回复汇总。
- 我的待办仅允许 `ADMIN` 和 `AGENT` 访问，并按当前登录用户 `assigneeId` 过滤。
- 我的待办状态仅包含 `PENDING_ASSIGN`、`PROCESSING`、`WAITING_CUSTOMER`。
- `limit` 默认 `10`，最大 `50`，小于 `1` 返回 `40001`。
- 我的待办排序：有 SLA 截止时间优先，按截止时间升序，再按创建时间倒序。

## 4. 页面口径

- PG-13 已确认进入契约阶段；原型底部状态覆盖区只作为评审说明，不作为前端常驻业务模块。
- 第一版不支持日期范围筛选，页面只展示统计截至时间。
- SLA 已超时数量来自 `summary.slaOverdueCount`；如需服务端按超时筛选列表，后续补工单列表 `slaBreached` 查询参数。
- 今日已关闭卡片第一版可跳转 `status=CLOSED` 列表；如需按关闭时间精确筛选，后续补关闭时间查询参数。
- 邮箱运行区第一版作为收件记录、发送日志、邮箱配置的快捷入口，不由工作台接口返回邮箱明细。
- 最近活动第一版作为后续扩展入口，不展示实时活动流。
