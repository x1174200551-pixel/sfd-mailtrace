## 1. 项目背景

### 1.1 背景说明

需要建设一套以**邮件为入口**的工单系统。客户通过发送邮件发起服务请求，系统自动创建工单并生成唯一跟踪编号（traceID / 工单号），同时向客户发送自动回执，并向对应处理人发送邮件提醒。处理人在系统中完成工单处理后，通过邮件回复客户，形成完整闭环。

本系统定位为**最基础的邮件工单流程**，参考开源 Helpdesk 产品 FreeScout 的能力边界，但采用自研方式实现，以便在 SLA 工作日计算、统计报表等方面按业务需求定制。

### 1.2 建设目标

1. 实现「客户发邮件 → 自动建单 → 自动回执 → 分配处理 → 处理回复 → 关闭工单」的基础闭环
2. 通过 IMAP 优先方式稳定收取客户邮件
3. 支持按**工作日**原则的 SLA 超时提醒
4. 为后续自动化统计报表**预留数据字段与菜单规划**（前期不实现报表功能）
5. 第一版在组织、部门、客户等角色模型上从简，降低实施复杂度

### 1.3 建设原则

- **先跑通主流程，再扩展高级能力**
- **角色模型从简**：组织、部门、客户可先合并或轻量实现
- **IMAP 优先于 POP3**（第一期仅实现 IMAP）
- **报表字段从建单第一天开始埋点，但报表功能前期仅规划不开发**
- **菜单规划按完整版设计，分两期交付：第一期做核心业务，第三期做报表**
- **建单优先于发信**：回执/通知失败不回滚工单
- **第一期仅后台回复客户**，不支持处理人邮件直回入单

## 2. 术语定义

| 术语 | 说明 |
|------|------|
| traceID / 工单号 | 系统自动生成的唯一工单编号，用于客户查询与邮件线程关联，如 `TCK-20260721-0001` |
| 工单 | 由客户邮件触发创建的服务请求记录 |
| Mailbox / 邮箱 | 系统监控的企业客服邮箱，如 `support@domain.com` |
| 自动回执 | 系统收到邮件后，自动回复客户的确认邮件，包含工单号 |
| 生命周期 | 工单从创建到关闭的全过程事件记录 |
| SLA | 服务级别协议，规定首次响应、解决等时效要求 |
| 工作日 SLA | 仅在工作日和工作时段内计算 SLA 时间 |
| IMAP | 邮件收取协议，邮件保留在服务器，适合工单系统 |
| POP3 | 邮件收取协议，邮件下载到本地，作为备选 |
| SMTP | 邮件发送协议，用于自动回执、通知、回复客户 |

## 3. 用户角色

### 3.1 角色定义

| 角色 | 说明 | 第一版策略 |
|------|------|-----------|
| 管理员 | 系统配置、邮箱配置、规则配置、用户管理 | 启用 |
| 处理人 | 接收工单、处理工单、回复客户 | 启用 |
| 主管 | 查看团队工单、SLA 超时 | 可选，第二版启用 |
| 客户 | 通过邮件发起工单，不登录后台 | 仅作为邮箱身份，不建复杂账号 |
| 组织 / 部门 | 内部组织结构 | 第一版可合并为默认组织 |

### 3.2 第一版角色简化策略

- **客户** = 发件人邮箱
- **处理人** = 系统用户 + 邮箱
- **组织 / 部门** = 暂不启用或统一为「默认组织」
- 后台仅保留：**管理员**、**处理人**

## 4. 业务需求

### 4.1 核心业务流程

```
客户发送邮件
    ↓
企业邮箱服务器
    ↓
系统通过 IMAP/POP3 拉取邮件
    ↓
解析邮件并创建工单（生成 traceID）
    ↓
并行执行：
  ├─ SMTP 自动回复客户（含工单号）
  └─ SMTP 通知对应处理人
    ↓
处理人处理工单
    ↓
SMTP 回复客户
    ↓
客户收到回复
    ↓
工单关闭，生命周期归档
```

| FR-001-02 | 系统支持通过 POP3 协议收取邮件（**后续版本**，第一期不做） | P2 |
| FR-001-03 | **第一期仅实现 IMAP**，作为唯一收信方式 | P0 |
| FR-001-04 | 支持配置拉取频率（建议 1～3 分钟） | P0 |

#### FR-002 工单创建

| 编号 | 需求描述 | 优先级 |
|------|---------|--------|
| FR-002-01 | 收到新邮件后自动创建工单 | P0 |
| FR-002-02 | 自动生成唯一 traceID / 工单号 | P0 |
| FR-002-03 | 工单号规则可配置，如 `TCK-{yyyyMMdd}-{seq}` | P1 |
| FR-002-04 | 记录邮件主题、正文、发件人、收件时间 | P0 |
| FR-002-05 | 记录来源邮箱（Mailbox） | P0 |
| FR-002-06 | 客户回复已有工单邮件时，应关联到原工单，而非重复建单 | P0 |
| FR-002-07 | 邮件关联须按固定优先级执行（见下方规则） | P0 |
| FR-002-08 | 关联失败时新建工单，并标记「疑似断链」 | P0 |

**邮件线程关联优先级（强制）：**

```
1. 优先匹配 In-Reply-To / References 中的 Message-ID
2. 其次匹配主题中的工单号（ticket_no），如 TCK-20260721-0001
3. 均无法匹配 → 新建工单，并打标签/标记「疑似断链」
```

| 编号 | 需求描述 | 优先级 |
|------|---------|--------|
| FR-003-01 | 新工单创建后，系统自动回复客户 | P0 |
| FR-003-02 | 自动回执内容必须包含 traceID / 工单号 | P0 |
| FR-003-03 | 自动回执模板可配置 | P0 |
| FR-003-04 | 自动回执通过 SMTP 发送 | P0 |
| FR-003-05 | 记录自动回执发送结果 | P0 |
| FR-003-06 | 回执发送失败不得回滚已创建工单（见失败策略） | P0 |

**自动回执模板示例：**

```
您好，

我们已收到您的邮件，工单编号：{ticket_no}

请保留此编号以便查询进度。回复本邮件时请勿删除工单号。

预计在工作日 1 个工作日内回复。

—— 客服中心
```

#### FR-004 分配与通知

| 编号 | 需求描述 | 优先级 |
|------|---------|--------|
| FR-004-01 | 新工单创建后，自动分配给处理人 | P0 |
| FR-004-02 | 支持默认处理人配置 | P0 |
| FR-004-03 | 支持按主题关键词分配 | P1 |
| FR-004-04 | 支持按来源邮箱分配 | P1 |
| FR-004-05 | 分配后通过邮件通知处理人 | P0 |
| FR-004-06 | 通知内容包含工单号、主题、客户邮箱、创建时间 | P0 |
| FR-004-07 | 支持手动转派 | P1 |
| FR-004-08 | 通知发送失败不得影响已完成的分配（见失败策略） | P0 |

#### FR-003/004 回执与通知失败策略（强制）

| 场景 | 处理原则 |
|------|---------|
| 工单创建 | **优先保证建单成功** |
| 自动回执失败 | 工单保留；写入 `MailSendLog`；进入重试队列；不回滚工单 |
| 处理人通知失败 | 分配结果保留；写入 `MailSendLog`；进入重试队列；不取消分配 |
| 重试 | 支持定时重试（如每 5 分钟）；超过最大次数后标记失败，供运维排查 |

#### FR-005 工单处理

| 编号 | 需求描述 | 优先级 |
|------|---------|--------|
| FR-005-01 | 处理人可在后台查看工单列表 | P0 |
| FR-005-02 | 处理人可查看工单详情 | P0 |
| FR-005-03 | 处理人**通过后台系统**回复客户 | P0 |
| FR-005-04 | 回复通过 SMTP 发送给客户 | P0 |
| FR-005-05 | 支持内部备注，不对客户可见 | P1 |
| FR-005-06 | 支持变更工单状态 | P0 |
| FR-005-07 | 支持关闭工单 | P0 |
| FR-005-08 | 首次响应时间仅在「对外回复客户」时记录 | P0 |
| FR-005-09 | **第一期不支持**处理人直接邮件回复客户并自动入单（后续可选） | — |

**处理入口约束（第一期强制）：**

- 处理人收到通知邮件后，进入**后台系统**查看并回复
- 内部备注**不算**首次响应，也不触发对外 SMTP
- 处理人若直接用个人邮箱回复客户，系统第一期**不识别、不入单**

#### FR-006 生命周期

| 编号 | 需求描述 | 优先级 |
|------|---------|--------|
| FR-006-01 | 系统记录工单全生命周期事件 | P0 |
| FR-006-02 | 生命周期至少包含：创建、自动回执、分配、首次响应、客户追信、SLA 预警、SLA 超时、关闭 | P0 |
| FR-006-03 | 每条事件记录操作人、时间、内容 | P0 |

#### FR-007 SLA 与提醒

| 编号 | 需求描述 | 优先级 |
|------|---------|--------|
| FR-007-01 | 支持配置首次响应 SLA | P0 |
| FR-007-02 | 支持配置解决 SLA | P1 |
| FR-007-03 | SLA 计算遵循**工作日原则** | P0 |
| FR-007-04 | 支持配置工作日（默认周一至周五） | P0 |
| FR-007-05 | 支持配置工作时段（如 9:00～18:00） | P0 |
| FR-007-06 | 支持配置节假日 | P0 |
| FR-007-07 | 支持即将超时提醒 | P0 |
| FR-007-08 | 支持已超时提醒 | P0 |
| FR-007-09 | 支持超时升级提醒（如通知主管） | P1 |
| FR-007-10 | 提醒方式默认采用邮件 | P0 |
| FR-007-11 | 首次响应口径：仅处理人经后台对外回复客户 | P0 |
| FR-007-12 | 非工作时间来信：从**下一个工作时段开始**起算 SLA | P0 |

**SLA 强制规则：**

| 项 | 规则 |
|----|------|
| 时长单位 | 以**工作日 / 工作小时**配置（默认首次响应 1 个工作日） |
| 起算时间 | 若创建时刻在非工作时段或节假日，从下一个工作日的工作时段起点起算 |
| 首次响应判定 | 仅「后台对外回复客户」；内部备注不算 |
| 即将超时默认阈值 | 剩余 **1 个工作小时**（可配置） |
| 已超时 | 超过截止时间后提醒处理人 |
| 升级提醒（P1） | 超时后超过 **4 个工作小时**可提醒主管（可配置；第一期可先不做主管角色） |

**SLA 示例：**

```
首次响应 SLA：1 个工作日
解决 SLA：3 个工作日

提醒规则：
- 剩余 1 个工作小时 → 提醒处理人
- 已超时 → 提醒处理人
- 超时 4 个工作小时 → 提醒主管（可选）
```

## 5. 工单状态设计

### 5.1 状态定义（第一期收敛）

| 状态 | 说明 |
|------|------|
| 待分配 | 工单已创建，尚未分配处理人 |
| 处理中 | 已分配处理人；含「尚未首次响应」与「已首次响应仍在处理」 |
| 待客户回复 | 处理人已对外回复，等待客户反馈 |
| 已关闭 | 工单结束 |
| 已取消 | 工单取消 |

> **说明：** 第一期不再单独使用「待首次响应」「已回复」状态，避免状态冗余。  
> 是否已首次响应用字段 `first_reply_at` 判断（为空 = 尚未首次响应）。

### 5.2 状态流转

```
待分配 → 处理中 → 待客户回复 → 已关闭
   ↓         ↓           ↓
 已取消     已取消       已取消
```

补充规则：

- 分配完成后：`待分配` → `处理中`
- 处理人首次/再次对外回复客户：进入或保持 `待客户回复`（并写入 `first_reply_at`，仅首次）
- 客户追信关联到原工单：`待客户回复` → `处理中`
- 处理人主动关闭：任意非终态 → `已关闭`

## 6. 后台菜单规划

### 6.1 一级菜单总览

完整版建议设置 **8 个一级菜单**：

```
1. 工作台
2. 工单中心
3. 客户与联系人
4. 邮件与邮箱
5. 规则与分配
6. SLA 与提醒
7. 统计报表（⏸ 前期仅规划，菜单可预留但不实现）
8. 系统管理
```

### 6.2 实施范围 vs 完整规划

| 菜单 | 第一期（实现） | 第三期（仅规划） |
|------|---------------|-----------------|
| 工作台 | ✅ | — |
| 工单中心 | ✅ | — |
| 客户与联系人 | ✅ 轻量 | — |
| 邮件与邮箱 | ✅ | — |
| 规则与分配 | ✅ | — |
| SLA 与提醒 | ✅ | — |
| 统计报表 | ⏸ 菜单预留 | ⏸ 后续实现 |
| 系统管理 | ✅ | — |

### 6.3 菜单详细结构

#### 6.3.1 工作台

**定位：** 处理人每天工作的首页

```
工作台
├── 概览看板
│   ├── 今日新建工单
│   ├── 待处理
│   ├── 处理中
│   ├── 即将超时
│   ├── 已超时
│   └── 今日已关闭
├── 我的待办
├── 我处理中
├── 我参与的
├── 即将超时
├── 已超时
└── 最近活动
    ├── 新分配给我
    ├── 客户新回复
    └── 系统提醒
```

> 前期工作台看板可只做基础计数，不做复杂图表。

**定位：** 核心业务菜单

```
工单中心
├── 全部工单

├── 处理中
├── 待客户回复
├── 已关闭
├── 已取消
└── 工单详情
    ├── 基本信息
    ├── 客户信息
    ├── 邮件往来
    ├── 生命周期
    ├── SLA 信息
    └── 操作区
        ├── 回复客户
        ├── 内部备注
        ├── 转派
        ├── 变更状态
        ├── 变更优先级
        └── 关闭工单
```

**工单列表字段：**

| 字段 | 说明 | 前期 |
|------|------|------|
| 工单号 | traceID | ✅ |
| 主题 | 邮件主题 | ✅ |
| 客户 | 客户邮箱/名称 | ✅ |
| 状态 | 待分配 / 处理中 / 待客户回复 / 已关闭 / 已取消 | ✅ |
| 是否已首次响应 | 由 `first_reply_at` 是否为空判断 | ✅ |
| 处理人 | 当前负责人 | ✅ |
| 来源邮箱 | 收到该工单的 Mailbox | ✅ |
| 创建时间 | | ✅ |
| 首次响应截止 | SLA 截止时间 | ✅ |
| 解决截止 | SLA 截止时间 | ✅ |
| 超时状态 | 正常 / 预警 / 超时 | ✅ |

#### 6.3.3 客户与联系人

**定位：** 客户主数据管理（第一版可轻量实现）

```
客户与联系人

├── 客户详情
│   ├── 基本信息
```

## 10. 实施分期

### 10.1 第一期：核心业务（原一、二期合并，约 4～5 周）

**目标：** 一次性交付完整邮件工单闭环，含分配规则与工作日 SLA

**交付菜单：**
- 工作台
- 工单中心
- 客户与联系人（轻量版）
- 邮件与邮箱
- 规则与分配
- SLA 与提醒
- 系统管理（用户、模板、编号规则）

**交付能力：**
- IMAP 收信（第一期不做 POP3）、自动建单、自动回执
- 邮件通知处理人；回执/通知失败可重试且不回滚工单
- 工单列表/详情、**仅后台回复客户**、生命周期记录
- 自动分配规则
- 工作日 SLA 计算与超时提醒（含起算规则与首次响应口径）
- 客户轻量只读列表
- **报表字段完整埋点**

**不包含：**
- 统计报表功能（菜单可预留占位）
- POP3 收信
- 处理人邮件直回自动入单
- 复杂客户 CRM / 组织部门
- 主管角色与超时升级（可配置预留，第一期可不启用）

## 11. 验收标准

### 11.1 第一期验收

- [ ] 客户发送邮件后，系统经 IMAP 自动创建工单
- [ ] 系统自动回复客户，邮件中包含工单号
- [ ] 系统邮件通知对应处理人
- [ ] 回执或通知失败时，工单仍保留，并可在发送记录中看到失败与重试
- [ ] 处理人可在后台查看并回复工单（第一期仅后台回复）
- [ ] 内部备注不触发对外邮件，也不记为首次响应
- [ ] 回复邮件可送达客户邮箱
- [ ] 客户再次回复时，按关联优先级挂回原工单；无法关联则新建并标记「疑似断链」
- [ ] 新工单可按规则自动分配
- [ ] SLA 按工作日/工作时段计算；非工作时间来信从下一工作时段起算
- [ ] 即将超时/已超时可邮件提醒
- [ ] 工单生命周期完整记录
- [ ] 工单状态符合收敛后的状态机
- [ ] 工单核心字段（含报表埋点字段）已完整记录
- [ ] 客户模块仅为邮箱去重列表 + 关联工单，无新建编辑档案

### 11.2 第三期验收（后续）

- [ ] 可查看工单量、响应时长、超时率等报表
- [ ] 可导出 Excel/CSV
- [ ] 可按处理人统计工作量

## 12. 风险与说明

| 风险 | 说明 | 应对 |
|------|------|------|
| 邮件送达率 | 自动回复可能进垃圾箱 | 配置 SPF/DKIM/DMARC |
| 邮件线程关联 | 客户回复可能无法关联原工单 | 强制关联优先级 + 主题保留工单号 + 断链标记 |
| 回执/通知失败 | SMTP 不稳定导致客户或处理人未收到 | 建单优先 + 发送日志 + 定时重试 |
| IMAP 兼容性 | 不同邮箱服务商配置差异大 | 第一期优先支持主流企业邮 IMAP |
| SLA 复杂度 | 工作日计算涉及节假日与起算点 | 单独 SLA 模块 + 明确起算/口径规则 |
| 处理人邮件直回 | 绕过系统导致状态不一致 | 第一期明确不支持，仅后台回复 |
| 报表数据缺失 | 前期不做报表但后续需要 | **从第一期开始完整埋点** |
