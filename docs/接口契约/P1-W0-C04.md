## 通用规则

- 所有接口需要 `Authorization: Bearer <token>`。
- 分配规则管理仅 `ADMIN` 可操作；非管理员返回 `403 / code=40302`。
- 第一版不做导出。
- 保存、启停、排序、删除仅影响后续新建工单匹配，历史工单不回写处理人。
- 匹配类型仅支持 `DEFAULT`、`SUBJECT_KEYWORD`、`MAILBOX`、`FROM_EMAIL`。
- 优先级 `priorityOrder` 数字越小越先匹配。

# 一、分配规则页面

对应原型：PG-08。

## GET /api/v1/assignment-rules

查询分配规则列表和摘要。

### 查询参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyword | string | 否 | 按规则名称、匹配值模糊搜索 |
| enabled | boolean | 否 | `true` 启用，`false` 停用 |
| matchType | string | 否 | `DEFAULT` / `SUBJECT_KEYWORD` / `MAILBOX` / `FROM_EMAIL` |

### 响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "records": [
      {
        "id": 100,
        "ruleName": "VIP 售后优先",
        "enabled": true,
        "priorityOrder": 10,
        "defaultRule": false,
        "matchType": "SUBJECT_KEYWORD",
        "matchValue": "VIP",
        "assigneeId": 2,
        "assigneeName": "验收客服",
        "notifyEnabled": true,
        "createdAt": "2026-07-27T10:06:00",
        "updatedAt": "2026-07-27T10:18:00"
      }
    ],
    "summary": {
      "totalCount": 8,
      "enabledCount": 6,
      "disabledCount": 2,
      "defaultCount": 1
    }
  }
}
```

### 页面映射

| 页面区域 | 字段 |
|------|------|
| 顶部统计 | `summary.totalCount`、`summary.enabledCount`、`summary.disabledCount`、`summary.defaultCount` |
| 规则列表 | `records[]` |
| 规则排序 | `priorityOrder` |
| 启停开关 | `enabled` |
| 默认兜底标签 | `defaultRule` |
| 匹配说明 | `matchType` + `matchValue` |
| 处理人 | `assigneeId` + `assigneeName` |
| 通知标识 | `notifyEnabled` |

## POST /api/v1/assignment-rules

新建分配规则。

### 请求

```json
{
  "ruleName": "VIP 售后优先",
  "enabled": true,
  "priorityOrder": 10,
  "defaultRule": false,
  "matchType": "SUBJECT_KEYWORD",
  "matchValue": "VIP",
  "assigneeId": 2,
  "notifyEnabled": true
}
```

### 校验

- `ruleName`：必填，最大 64 字符。
- `priorityOrder`：1-9999。
- `matchType`：必填，只允许 `DEFAULT`、`SUBJECT_KEYWORD`、`MAILBOX`、`FROM_EMAIL`。
- `matchValue`：最大 256 字符；`DEFAULT` 可为空，其他类型必填。
- `assigneeId`：必填，必须是存在且启用的处理人。
- `defaultRule=true` 时，`matchType` 必须为 `DEFAULT`；默认规则只能存在一条。
- `FROM_EMAIL` 的 `matchValue` 必须是合法邮箱或合法邮箱域名后缀。

## PUT /api/v1/assignment-rules/{id}

编辑分配规则。请求体同新建接口。

## PATCH /api/v1/assignment-rules/{id}/enabled

启用或停用规则。

### 请求

```json
{
  "enabled": false
}
```

### 响应

返回最新 `AssignmentRuleVO`。

## PUT /api/v1/assignment-rules/sort

批量调整规则优先级。

### 请求

```json
{
  "rules": [
    { "id": 100, "priorityOrder": 10 },
    { "id": 101, "priorityOrder": 20 }
  ]
}
```

### 校验

- `rules` 不能为空。
- `id` 必填。
- `priorityOrder` 必填，范围 1-9999。
- 同一次请求内规则 ID 不允许重复。

## POST /api/v1/assignment-rules/test-match

测试输入的新工单信息会命中哪条分配规则。

### 请求

```json
{
```


### 响应：未命中

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "matched": false,
    "ruleId": null,
    "ruleName": null,
    "matchType": null,
    "matchValue": null,
    "assigneeId": null,
    "assigneeName": null,

```

## DELETE /api/v1/assignment-rules/{id}

删除分配规则。

### 页面要求

- 删除前必须二次确认。
- 删除后列表刷新。
- 删除不影响历史工单已分配处理人。

## 四态约定

| 状态 | 页面表现 |
|------|----------|
| 加载中 | 规则列表、编辑区和测试区禁用操作，显示骨架或加载状态 |
| 空列表 | 展示新建规则入口和默认规则说明 |
| 接口失败 | 保留筛选/表单输入，展示错误提示和重试入口 |
| 无权限 | 非管理员只读或显示无权限页；隐藏新建、保存、启停、排序、删除按钮 |

# 二、SLA 策略页面

对应原型：PG-09。

## GET /api/v1/sla-policies

查询 SLA 策略列表和摘要。

### 查询参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyword | string | 否 | 按策略名称模糊搜索 |
| enabled | boolean | 否 | `true` 启用，`false` 停用 |
| defaultPolicy | boolean | 否 | `true` 默认策略，`false` 非默认策略 |

```json
{

    "records": [

        "defaultPolicy": true,
        "responseHours": 2,
        "resolveHours": 16,
        "warningRemainHours": 1,
        "escalateAfterBreachHours": 2,

        "createdAt": "2026-07-27T10:26:00",
        "updatedAt": "2026-07-27T11:58:00"
      }
    ],
    "summary": {
      "totalCount": 5,
      "enabledCount": 4,
      "disabledCount": 1,
      "defaultCount": 1
    }
  }
}
```

### 页面映射

| 页面区域 | 字段 |
|------|------|
| 顶部统计 | `summary.totalCount`、`summary.enabledCount`、`summary.disabledCount`、`summary.defaultCount` |
| 策略列表 | `records[]` |
| 默认标签 | `defaultPolicy` |
| 启停开关 | `enabled` |
| 时限配置 | `responseHours`、`resolveHours`、`warningRemainHours`、`escalateAfterBreachHours` |
| 绑定日历 | `calendarId`，前端用工作日历列表回显名称、时区、工作日和时段 |

## GET /api/v1/work-calendars

SLA 策略编辑区加载日历下拉和预览信息。

### 查询参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyword | string | 否 | 按日历名称模糊搜索；页面默认不传 |
| defaultCalendar | boolean | 否 | 默认日历筛选；页面默认不传 |

### 页面映射

| 页面区域 | 字段 |
|------|------|
| 绑定日历下拉 | `records[].id`、`calendarName`、`timezone`、`workdays`、`workStartTime`、`workEndTime` |
| SLA 预览 | 当前策略 `calendarId` 匹配到的 `WorkCalendarVO` |

## POST /api/v1/sla-policies

新建 SLA 策略。

### 请求

```json
{
  "policyName": "VIP 客户 2 小时响应",
  "enabled": true,
  "defaultPolicy": false,
  "responseHours": 2,
  "resolveHours": 16,
  "warningRemainHours": 1,
  "escalateAfterBreachHours": 2,
  "calendarId": 1
}
```

### 校验

- `policyName`：必填，最大 64 字符。
- `responseHours`：必填，1-9999。
- `resolveHours`：可空；填写时不能小于 `responseHours`。
- `warningRemainHours`：必填，1-9999，且必须小于 `responseHours`。
- `escalateAfterBreachHours`：可空，1-9999。
- `calendarId`：必填，必须是存在的工作日历。
- `defaultPolicy=true` 时，策略必须启用；默认策略唯一。

## PUT /api/v1/sla-policies/{id}

编辑 SLA 策略。请求体同新建接口。

## PATCH /api/v1/sla-policies/{id}/enabled

启用或停用策略。

### 请求

```json
{
  "enabled": false
}
```

### 页面要求

- 默认 SLA 策略不能停用；接口返回错误时前端保留当前表单和列表筛选。
- 启停只影响后续新建工单 SLA 计算，历史工单已有 SLA 字段不自动重算。

## PATCH /api/v1/sla-policies/{id}/default

设置或取消默认 SLA 策略。

### 请求

```json
{
  "defaultPolicy": true
}
```

### 页面要求

- 停用策略不能设为默认。
- 设为默认后后端清理其他默认策略，前端刷新列表。
- 默认策略用于后续新工单，没有匹配到更具体策略时的 SLA 计算。

## DELETE /api/v1/sla-policies/{id}

删除 SLA 策略。

### 页面要求

- 删除前必须二次确认。
- 默认策略不能删除。
- 删除后列表刷新；历史工单已有 SLA 字段不回写。

## SLA 预览约定

- 页面预览不调用额外后端接口，前端根据表单值和已加载的工作日历做即时估算。
- 示例建单时间固定为 `2026-07-27 15:30`，便于与 PG-09 原型核对。
- 预览展示首次响应截止、解决截止、预警和超时升级时间线；最终截止时间以后台建单时 `SlaDeadlineService` 计算结果为准。

## 四态约定

| 状态 | 页面表现 |
|------|----------|
| 加载中 | 策略列表、编辑区、日历下拉和 SLA 预览显示加载或禁用操作 |
| 空列表 | 展示新建策略入口，并提示必须至少保留一个启用默认策略 |
| 接口失败 | 保留筛选/表单输入，展示错误提示和重试入口 |
| 无权限 | 非管理员显示无权限页；隐藏新建、保存、启停、默认和删除按钮 |

# 三、工作日历/节假日页面

对应原型：PG-10。

## GET /api/v1/work-calendars

查询工作日历列表和摘要。

### 查询参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyword | string | 否 | 按日历名称模糊搜索 |

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "records": [
      {
        "id": 1,
        "calendarName": "客服工作日历",

        "workdays": [1, 2, 3, 4, 5],
        "workStartTime": "09:00",
        "workEndTime": "18:00",
        "defaultCalendar": true,
        "createdAt": "2026-07-27T10:33:00",
        "updatedAt": "2026-07-27T14:48:00"
      }
    ],
    "summary": {
      "totalCount": 3,
      "defaultCount": 1
    }
  }
}
```

### 页面映射

| 页面区域 | 字段 |
|------|------|
| 顶部统计 | `summary.totalCount`、`summary.defaultCount` |
| 日历列表 | `records[]` |
| 默认标识 | `defaultCalendar` |
| 日历名称 | `calendarName` |
| 时区 | `timezone` |
| 工作日 | `workdays`，1=周一，7=周日 |
| 工作时段 | `workStartTime`、`workEndTime` |

| 本月节假日数 | 不来自工作日历接口；前端用节假日列表当前月份结果统计 |

## POST /api/v1/work-calendars

新建工作日历。

### 请求

```json
{
  "calendarName": "客服工作日历",
  "timezone": "Asia/Shanghai",
  "workdays": [1, 2, 3, 4, 5],
  "workStartTime": "09:00",
  "workEndTime": "18:00",
  "defaultCalendar": false
}
```

### 校验

- `calendarName`：必填，最大 64 字符。
- `timezone`：必填，最大 64 字符，必须是合法 `ZoneId`，默认 `Asia/Shanghai`。
- `workdays`：必填，至少一天；仅允许 1-7；不能重复；后端按升序保存。
- `workStartTime` / `workEndTime`：必填，格式 `HH:mm` 或 `HH:mm:ss`。
- 工作开始时间必须早于工作结束时间。
- `defaultCalendar=true` 时，不能已有其他默认日历；如要切换默认，使用 `PATCH /api/v1/work-calendars/{id}/default`。

## PUT /api/v1/work-calendars/{id}

编辑工作日历。请求体同新建接口。

### 页面要求

- 保存后只影响后续 SLA 计算；历史工单已有响应截止和解决截止不自动重算。
- 接口失败时保留当前筛选、表单输入和选中日历。

## PATCH /api/v1/work-calendars/{id}/default

设置或取消默认工作日历。

### 请求

```json
{
  "defaultCalendar": true
}
```

### 页面要求

- 设为默认后后端会清理其他默认工作日历，前端刷新列表。
- 默认工作日历不可直接删除；页面应禁用删除按钮并展示原因。

## DELETE /api/v1/work-calendars/{id}

删除工作日历。

### 删除保护

- 默认工作日历不能删除。
- 已被 SLA 策略引用的工作日历不能删除。
- 已配置节假日的工作日历不能删除。
- 删除前必须二次确认；删除后刷新日历列表和节假日列表。
- 删除不影响历史工单已有 SLA 截止时间。

## GET /api/v1/holidays/national-presets

按年份获取国家法定节假日模板。后端请求三方节假日 API 并转换为当前系统可导入的 `holidayDate + holidayName` 结构；前端不维护年份数据。

### 查询参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| year | number | 是 | 模板年份，例如 `2026` |

### 响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "year": 2026,
    "sourceName": "节假日API",
    "sourceUrl": "https://api.jiejiariapi.com/v1/holidays/2026",
    "supportedYears": [2026],
    "records": [
      {
        "holidayDate": "2026-10-01",
        "holidayName": "国庆节"
      }
    ],
    "makeupWorkdayDates": ["2026-10-10"]
  }
}
```

### 页面要求

- 快捷导入按钮按当前选择月份的年份调用该接口。
- 只把 `records[]` 创建为节假日；`makeupWorkdayDates[]` 当前仅作接口返回说明，不写入节假日表。
- 已存在的 `holidayDate` 自动跳过，避免重复导入。
- 三方接口不可用时展示错误提示，不影响手工新增、编辑、删除节假日。

## POST /api/v1/holidays

新建节假日。

### 请求

```json
{
  "calendarId": 1,
  "holidayDate": "2026-10-01",
  "holidayName": "国庆节"
}
```

### 校验

- `calendarId`：必填，必须是存在的工作日历。
- `holidayDate`：必填。
- `holidayName`：必填，最大 64 字符。
- 同一工作日历下 `holidayDate` 唯一。
- 当前后端不扩展“是否全天”字段，页面不展示该控件。

## PUT /api/v1/holidays/{id}

编辑节假日。请求体同新建接口。

## DELETE /api/v1/holidays/{id}

删除节假日。

### 页面要求

- 删除前必须二次确认。
- 删除后刷新节假日列表、月历预览和 SLA 计算示例。
- 删除不影响历史工单已有 SLA 截止时间。

## 月历预览和 SLA 计算示例

- 月历预览不调用单独接口；前端根据当前工作日历 `workdays`、`workStartTime`、`workEndTime` 和当前月份节假日列表渲染。
- SLA 计算示例不作为最终业务计算接口；页面可用固定示例时间演示节假日跳过和工作小时累加。
- 实际新工单的响应/解决截止时间以后台 `SlaDeadlineService` 计算并写入的字段为准。

## 四态约定

| 状态 | 页面表现 |
|------|----------|
| 加载中 | 日历列表、编辑区、节假日列表和预览禁用操作，显示加载状态 |

# 五、工作台页面

对应原型：PG-13。

## 第一版边界

- 工作台第一版只承接已完成后端接口：`GET /api/v1/dashboard/summary` 和 `GET /api/v1/dashboard/my-todos`。
- 页面中的风险入口、邮箱入口、处理中入口通过现有页面跳转和筛选实现，不新增工作台聚合接口。
- 原型中的最近活动为后续扩展入口，第一版不展示实时活动流。
- 原型底部状态覆盖区仅用于 PG-13 评审，不作为前端页面常驻业务模块。
- 第一版不支持日期范围筛选；顶部只展示“统计截至时间”，刷新后更新数据。

- 点击待办卡片进入 `GET /api/v1/tickets/{id}` 对应工单详情。

- 邮箱入口进入收件记录、发送日志或邮箱配置已有页面，不通过工作台接口返回邮箱详情。

## 权限与错误

| 场景 | HTTP/code | 页面处理 |
|------|------|------|
| 未登录 | `403 / 40302` | 跳转登录或显示无工作台查看权限 |
| 非管理员且非处理人 | `403 / 40302` | 隐藏工作台入口；直达页面展示无工作台查看权限 |
| `limit < 1` | `400 / 40001` | 保留页面，待办区提示参数错误 |
| 接口超时或网络失败 | 网络错误 | 保留其他已成功模块，失败模块展示重试 |

## Service 层步骤对齐

已对齐 `DashboardService.summary`：

- 1、工作台仅允许 `ADMIN` 和 `AGENT` 访问。
- 2、按工单状态统计 `pendingAssignCount`、`processingCount`、`waitingCustomerCount`。
- 3、按 `sla_breached=1` 统计 `slaOverdueCount`。
- 4、按今日关闭口径统计 `closedTodayCount`。
- 5、`activeCount = pendingAssignCount + processingCount + waitingCustomerCount`。

已对齐 `DashboardService.myTodos`：

- 1、待办仅允许 `ADMIN` 和 `AGENT` 访问，并按当前登录用户 `assigneeId` 过滤。
- 2、待办状态仅包含 `PENDING_ASSIGN`、`PROCESSING`、`WAITING_CUSTOMER`。
- 3、`limit` 默认 `10`，最大 `50`，小于 `1` 返回 `40001`。
- 4、排序规则为有 SLA 截止时间优先，按 `slaResponseDeadline` 升序，再按 `createdAt` 倒序。
- 5、返回待办列表和同一口径下的 `totalCount`、`processingCount`、`waitingCustomerCount`、`slaOverdueCount`。

## 四态约定

| 状态 | 页面表现 |
|------|----------|
| 加载中 | 统计卡片、SLA 风险摘要、待办列表展示骨架；刷新按钮进入 loading，不重复触发 |
| 空列表 | 无工单、无待办或无风险数据时展示空态；保留刷新和跳转入口，不展示假数据 |
| 接口失败 | 模块级失败模块展示错误说明和重试；其他成功模块继续展示最近一次成功数据 |
| 无权限 | 隐藏工作台入口；直达页面展示无工作台查看权限，不暴露接口错误 |

## 后续扩展

- SLA 达成率、预警类指标、关闭时间筛选、活动流、消息流如需上线，应先补后端字段或独立接口契约。
- 最近活动可后续由操作日志、SLA 提醒事件、收发日志聚合，第一版不阻断工作台上线。
